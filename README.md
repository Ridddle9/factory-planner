# Factory Planner — планирование производства

B2B веб-приложение для планирования производства. Прикладной кейс: завод по производству светотехники.

**Содержание:** [Контекст](#контекст-и-цели) · [Модель данных](#модель-данных) · [Разработка](#разработка) · [API](#api) · [История изменений](#история-изменений)

---

## Контекст и цели

**Задача:** заменить ручной обмен Excel-файлами между офисом и производством на единую веб-систему.

**Пользователи:**
- **Планировщик** — загрузка заказов из 1С, формирование и корректировка плана, сводка факта
- **Начальник цеха** — распределение бригад, ввод фактического выпуска и комментариев

**Проблемы текущего процесса:** ручной обмен файлами, риск рассинхронизации, дублирование данных, нет единого источника правды.

## Модель данных

| Сущность | Описание |
|----------|----------|
| **Workshop** | Участок/цех. Группировка категорий. |
| **ProductCategory** | Категория номенклатуры. Содержит мощность на бригаду/день. |
| **Product** | Номенклатура: код, название, категория. |
| **Team** | Бригада. Привязывается к категориям через CategoryTeam. |
| **TeamDayCapacity** | Корректировка мощности бригады на конкретный день (фактор 0.0–1.0, причина). |
| **Order** | Заказ клиента: номер, клиент, срок, менеджер. |
| **OrderItem** | Позиция заказа: товар, количество, «к обеспечению» (вычисляется). |
| **DailyTask** | Задача на день: позиция + дата + план + факт + комментарий. |

### Ключевые связи

- `ProductCategory` ↔ `Team` — many-to-many через `CategoryTeam`
- `Order` → `OrderItem[]`
- `OrderItem` → `DailyTask[]`
- `DailyTask` → `OrderItem`, `Team`, дата
- `Team` → `TeamDayCapacity[]`

### Модель нагрузки бригады

Нагрузка считается в долях бригадо-дня: `load = Σ(plannedQuantity / capacityPerTeamPerDay)` по всем задачам бригады за день.

- `load = 1.0` — полный рабочий день
- `load > 1.0` — перегруз
- `TeamDayCapacity.factor` — доступная доля дня (например, `0.7` = вышло 7 из 10 человек)

Это позволяет корректно складывать задачи по разным категориям: 100 LUM (cap=220) + 100 IP (cap=170) = `100/220 + 100/170 ≈ 1.04` (перегруз).

## Интерфейс

### Справочники

- **Участки** — CRUD цехов/участков
- **Категории** — CRUD категорий с мощностью; кнопка «Бригады» для привязки бригад к категории
- **Товары** — CRUD номенклатуры
- **Бригады** — две вкладки:
  - **Список бригад** — CRUD
  - **Мощности по дням** — сетка-календарь на 2 недели; клик на ячейку задаёт фактор мощности и причину (например «0.7 — вышло 7 из 10 человек»). После сохранения система проверяет, не превышает ли текущий план новую мощность — если да, показывает перегруз в % бригадо-дня и предлагает перенести излишек на следующий день

### Заказы

Две вкладки:
- **Актуальные** — заказы, где факт выпуска ещё не подтверждён по всем позициям. Показываются колонки «Срок договора» и «Готово по плану» (прогноз по текущим задачам, красный если позже срока)
- **Архив** — заказы, где факт выпуска подтверждён по всем позициям (completionPct = 100%)

На каждой позиции заказа:
- **Автоплан** — автоматически распределяет количество по датам с учётом мощностей и загрузки бригад
- **Перепланировать заказ** — удаляет старые задачи и распределяет заново

### График (главный экран работы)

Гант-таблица: строки — позиции заказов, колонки — даты.

**Структура строк:**
- Участки выделены строками-разделителями на всю ширину
- Бригада объединяет подряд идущие строки через `rowspan`
- Колонка «Заказ / Товар»: сверху жирно номер заказа, снизу название товара

**Взаимодействие через клик на ячейку:**

| Ячейка | Действие |
|--------|----------|
| Пустая | Создать задачу на эту дату |
| Заполненная | Попап: редактировать количество и бригаду |
| Попап → «Перенести →» | Жёлтый баннер, пустые ячейки той же строки подсвечиваются — кликни нужную |
| Попап → «Разбить ÷» | Форма: сколько перенести + на какую дату + проверка загрузки бригады |

**В шапке колонок** — цветная полоска нагрузки (зелёный / жёлтый / красный). При наведении появляется карточка с разбивкой загрузки по каждой бригаде в процентах.

**Разбивка задачи (детально):**
1. Выбираешь количество для переноса и дату
2. Жмёшь «Проверить загрузку» → система показывает свободную ёмкость бригады в штуках для данной категории
3. Если бригада перегружена — предупреждение; кнопка «Разбить» всё равно доступна

### Аналитика и планирование

Вкладки:
- **Перегрузка** — задачи, запланированные позже срока поставки
- **Недогрузка** — бригады с загрузкой < 100% бригадо-дня; показывается в % (не в штуках), корректно для смешанных категорий
- **Загрузка бригады** — матрица категория × дата с utilization по каждой категории
- **Статус заказов** — прогноз дат завершения, процент выполнения

Кнопка **«Перепланировать очередь»** — удаляет незапущенные задачи и заново планирует все позиции в порядке от старых заказов к новым (по дате согласования).

### Импорт Excel / 1С

Загрузка файла «первичка new» из 1С. Система создаёт или обновляет категории (мощность парсится из названия `(N max)`), товары, заказы, позиции.

**Автоматическая запись факта.** При повторной загрузке система сравнивает «К обеспечению» из файла с предыдущим значением в БД (`orderItem.quantity`). Разница записывается как `actualQuantity` за вчерашний день:

```
calculatedFact = K_предыдущий − K_текущий
```

Если K снизился — факт записывается автоматически. Если строка попала в конфликт (вчерашний факт введён вручную и расходится с расчётным) — в ответе возвращается `conflicts[]` для ручного разрешения.

**Строки с K = 0** (последняя партия полностью произведена) не пропускаются: `actualQuantity = K_предыдущий`, план-задачи не создаются.

**`possiblyCompleted`** — список позиций, у которых вчера был план без факта, но они не появились в текущем импорте. Типичная причина: K стал 0 и ERP не включила строку в выгрузку. Требует ручной проверки.

После импорта → «Перепланировать очередь» в разделе Аналитика.

## История изменений

### [текущая] — апрель 2026

- **Модель нагрузки** — рефакторинг на дробный бригадо-день: `load = Σ(qty / capacityPerTeamPerDay)`. Корректно складывает задачи по разным категориям. Затронуто: `calculateTeamLoad`, `autoPlanOrderItem`, `selectTeamWithMinLoad`, все аналитические эндпоинты
- **График: группировка строк** — участки как строки-разделители (не колонка), бригады объединены через `rowspan`
- **График: колонка «Заказ / Товар»** — сверху номер заказа, снизу название товара
- **График: тултип нагрузки** — при наведении на полоску в шапке дня появляется карточка с разбивкой по бригадам (%, цветовая индикация)
- **Заказы: две вкладки** — «Актуальные» (не все позиции подтверждены фактом) и «Архив» (completionPct = 100%)
- **Заказы: прогноз даты** — колонка «Готово по плану» с датой последней задачи по текущему плану; красная если позже срока договора
- **Исправление факта (импорт):** `calculateRemainingQuantity` теперь возвращает `orderItem.quantity` напрямую — ранее вычитал уже записанные факты, из-за чего со второго дня `calculatedFact` всегда был 0
- **Исправление K=0 (импорт):** строки с «К обеспечению» = 0 больше не пропускаются; весь остаток записывается как факт
- **`possiblyCompleted` (импорт):** новое поле в ответе — позиции с вчерашним планом, не попавшие в текущий импорт (вероятно K → 0, строка исчезла из выгрузки ERP)
- **Исправление `completionPct`:** расчёт переключён на `produced / (K + produced)`, что исключает значения > 100% при перевыполнении
- **Синтетические тест-данные:** `scripts/generate-test-xlsx.mjs` генерирует Excel-файлы для 5 сценариев плана/факта; `scripts/verify-fact.mjs` проверяет БД после импорта

### Фаза 3 (ранее)

- **График (Гант)** — кликабельные ячейки: создание, редактирование, перенос, разбивка прямо в таблице
- **Разбивка задачи** — форма с выбором количества и даты; проверка загрузки бригады перед сохранением
- **Перенос задачи** — визуальный режим: подсветка доступных ячеек, клик для переноса

- **Перебалансировка при сниженной мощности** — после сохранения фактора система проверяет перегрузку и предлагает перенести излишек на следующий день
